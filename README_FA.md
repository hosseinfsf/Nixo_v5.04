# Nixo v5.04 — Trading Modes + Advanced Analytics + Telegram Dual Roulette

این بسته برای ادامه توسعه Nixo و دریافت سیگنال متنی از کانال‌های تلگرام ساخته شده است. پل Python فقط پیام را می‌خواند و به صف مشترک MT5 می‌نویسد؛ **خود اکسپرت تصمیم می‌گیرد پیام را در Paper Lab آزمایش کند یا پس از فعال‌سازی صریح کاربر، سفارش واقعی بفرستد.**

## چه چیزهایی فعال شده‌اند؟

- خواندن پیام‌های متنی کانال‌های تلگرام با حساب تلگرامی خودت (Telethon).
- افزودن، ویرایش، روشن/خاموش و حذف چند منبع از طریق Source Manager.
- تشخیص سیگنال‌های متنی متداول BUY/SELL، نماد، Market/Limit/Stop، محدوده Entry، حدضرر و تا سه هدف.
- تشخیص پیام‌های اصلاح SL/TP، انتقال SL به BE، CLOSE و CANCEL.
- چهار مدل آزمایشی A/B/C/D برای مقایسه مدل پایه، رولت تعداد اردر، رولت حجم و هر دو با هم.
- مدل پیش‌فرض Live برابر `D_COMBINED` است؛ یعنی **هر دو رولت تعداد اردر و حجم** برای کپی واقعی انتخاب شده‌اند.
- وضعیت رولت هر کانال جداگانه ذخیره می‌شود؛ سقف پوزیشن‌ها و سقف ریسک، محدودیت مشترک حساب هستند.
- حدضرر روی سرور بروکر می‌ماند؛ TPها به‌صورت مرحله‌ای توسط اکسپرت اجرا می‌شوند تا TP3 کل حجم را ناخواسته نبندد.
- بعد از TP3، در صورت امکان تقسیم حجم، ۱۲٫۵٪ باقی‌مانده Runner می‌شود و با ATR Trailing مدیریت می‌شود.

## ۱) پیش‌نیازها

- ویندوز و MetaTrader 5 دسکتاپ.
- Python 3.10 یا جدیدتر؛ بسته Telethon در زمان ساخت از شاخه 1.45 استفاده می‌کند.
- حساب MT5 از نوع **Hedging** برای کپی زنده و خروج‌های جزئی. در حساب Netting، این موتور کپی زنده را رد می‌کند؛ بستن جزئی با `PositionClosePartial` در MT5 برای حالت Hedging مستند شده است.
- اکسپرت باید روی نمودار همان نماد نصب شود که سیگنال قرار است روی آن اجرا شود؛ برای نمونه XAUUSD یا نماد طلای بروکر با پسوند.

## ۲) دریافت API ID و API HASH تلگرام

1. با حساب تلگرام خودت وارد [my.telegram.org](https://my.telegram.org) شو.
2. به بخش **API development tools** برو و یک Application ثبت کن.
3. مقدارهای `api_id` و `api_hash` را دریافت کن.
4. در پوشه `bridge` فایل `.env.local.example` را به `.env.local` کپی کن.
5. `TELEGRAM_API_ID` و `TELEGRAM_API_HASH` را در `.env.local` قرار بده.

این حساب باید از قبل عضو کانال خصوصی موردنظر باشد یا به کانال عمومی دسترسی داشته باشد. نسخه فعلی Source Manager نام کاربری کانال عمومی را می‌گیرد؛ لینک دعوت خصوصی بدون username در این نسخه به‌صورت خودکار resolve نمی‌شود.

**هشدار امنیتی:** کد ورود تلگرام، رمز دومرحله‌ای، API HASH یا فایل `nixo_telegram.session` را برای هیچ‌کس ارسال نکن. فایل Session حاوی کلید مجوز ورود است و هرکس به آن دسترسی داشته باشد می‌تواند به حساب تلگرام وارد شود. این اطلاعات فقط روی کامپیوتر خودت بمانند.

## ۳) افزودن کانال تلگرام

1. وارد پوشه `bridge` شو.
2. فایل `manage_sources.bat` را اجرا کن.
3. گزینه `2) Add` و سپس `1) Telegram channel` را انتخاب کن.
4. نام نمایشی دلخواه و username کانال را وارد کن (بدون `@`).
5. Allowed symbols را مثلاً `XAUUSD` بگذار.
6. اگر کانال نماد را در متن پیام نمی‌نویسد، فقط در صورتی `Assume this source's only symbol if ticker is omitted` را Yes کن که کانال واقعاً فقط همان نماد را ارسال می‌کند.
7. برای `Enable this source now?` پاسخ Yes بده.
8. برای هر کانال دیگر همین مراحل را تکرار کن. هر منبع باید Source ID مستقل داشته باشد.

فایل تنظیم منبع‌ها `config/sources.json` است. بسته با فهرست خالی شروع می‌شود تا هیچ کانال نمونه‌ای به‌طور ناخواسته فعال نباشد.

## ۴) راه‌اندازی پل تلگرام

1. در پوشه `bridge`، فایل `start_bridge.bat` را اجرا کن.
2. فایل BAT به‌صورت خودکار یک محیط Python محلی می‌سازد و وابستگی‌های `requirements.txt` را نصب می‌کند.
3. در اولین اجرا Telethon از تو شماره تلفن را در پنجره Command Prompt می‌پرسد؛ شماره را با کد کشور وارد کن.
4. کد ورود ارسال‌شده از سمت تلگرام و در صورت نیاز رمز دومرحله‌ای را همان‌جا وارد کن.
5. پس از ورود موفق باید پیام `Listening Telegram` برای کانال‌های روشن‌شده را ببینی.
6. این پنجره باید هنگام دریافت سیگنال باز بماند. برای کار مداوم می‌توانی از VPS ویندوزی استفاده کنی.

هر پیام معتبر به پوشه مشترک متاتریدر در `Common\Files\NixoBridge\inbox` فرستاده می‌شود. اگر MT5 چند نصب دارد و Common Files خودکار اشتباه تشخیص داده شد، مسیر درست را در `MT5_COMMON_FILES` داخل `.env.local` بنویس.

برای تست Parser بدون ورود تلگرام، در پوشه `bridge` اجرا کن:

```bat
py -3 signal_bridge.py --self-test
```

## ۵) نصب اکسپرت در MT5

1. فایل `mt5/Nixo_v5.04_TradingModes_AdvancedAnalytics.mq5` را در پوشه `MQL5/Experts` متاتریدر کپی کن.
2. در MetaEditor فایل را باز و با F7 کامپایل کن.
3. اکسپرت را روی نمودار نماد موردنظر قرار بده.
4. مطمئن شو `InpSignalLabEnabled = true` باشد.
5. `InpSignalLiveModel = SIGNAL_MODEL_D_COMBINED` را نگه دار؛ این گزینه هر دو رولت را انتخاب می‌کند.
6. در مرحله آزمایش، حتماً `InpSignalLiveAllowed = false` بماند.
7. دکمه Algo Trading متاتریدر باید روشن باشد تا آزمایش‌های Paper و بعداً سفارش واقعی طبق تنظیمات اجرا شوند.

## ۶) منطق دو رولت

### رولت تعداد اردر (Order Roulette)

- شروع پیش‌فرض: ۱ سفارش برای هر سیگنال.
- بعد از بسته‌شدن کل سبد با سود خالص: تعداد پله‌ای دو برابر می‌شود؛ نمونه ۱ ← ۲ ← ۴ ← ۸.
- بعد از بسته‌شدن کل سبد با زیان خالص: یک واحد از تعداد کم می‌شود؛ حداقل ۱.
- سقف پیش‌فرض: `InpSignalMaxOrderCount = 8`.

### رولت حجم (Volume Roulette)

- شروع پیش‌فرض: پله ۱.
- بعد از سبد سودده: یک پله افزایش؛ بعد از سبد زیان‌ده: یک پله کاهش؛ حداقل پله ۱.
- سقف پیش‌فرض: `InpSignalMaxVolumeStep = 5`.
- با `InpSignalVolumeStepFactor = 1.0` ضریب حجم پله‌ها ۱x، ۲x، ۳x، ۴x و ۵x است.

### اثر گزینه Split Risk Across Orders

- `false` (پیش‌فرض): حجم هر سفارش بر اساس پله رولت حجم باقی می‌ماند و با زیادشدن تعداد سفارش‌ها، حجم کل سبد هم بیشتر می‌شود. این حالت اثر هر دو رولت را هم‌زمان نشان می‌دهد.
- `true`: حجم کل سبد بین تعداد سفارش‌ها تقسیم می‌شود تا با افزایش تعداد سفارش، ریسک/حجم کل تقریباً ثابت بماند.

هر کانال پله‌های مستقل دارد؛ ولی `InpSignalMaxLivePositions` و `InpSignalMaxLiveRiskPct` سقف مشترک حساب هستند. پیش‌فرض سقف ریسک باز سیگنال‌ها ۰٫۵٪ Equity است. افزایش تعداد/حجم، احتمال برد را بیشتر نمی‌کند؛ فقط میزان مواجهه مالی را تغییر می‌دهد.

## ۷) حدضرر، TPها و Runner

- SL واقعی روی سرور بروکر قرار می‌گیرد.
- TP1، TP2 و TP3 توسط EA مدیریت می‌شوند؛ بروکر برای کل پوزیشن TP نهایی جداگانه نمی‌گیرد، چون آن کار می‌توانست باقی حجم را پیش از فعال‌شدن Runner ببندد.
- در هر مرحله، درصد خروج از **حجم باقی‌مانده همان لحظه** حساب می‌شود: TP1=۵۰٪، TP2=۵۰٪، TP3=۵۰٪. در حالت ایده‌آل، ۵۰٪ + ۲۵٪ + ۱۲٫۵٪ از حجم اولیه بسته شده و ۱۲٫۵٪ باقی‌مانده Runner است.
- حداقل حجم و گام حجم بروکر ممکن است Partial Close را غیرممکن کند. اگر TP1/TP2 قابل تقسیم نباشد، EA حجم را نگه می‌دارد و سطح حفاظتی SL را جلو می‌آورد؛ اگر در TP3 امکان باقی‌گذاشتن Runner معتبر وجود نداشته باشد، باقی حجم در TP3 بسته می‌شود.
- برای باقی‌ماندن دقیق ۱۲٫۵٪، حجم اولیه باید با حداقل/گام حجم بروکر قابل تقسیم به هشت قسمت معتبر باشد. برای نمونه، با گام ۰٫۰۱ لات، حجم کل ۰٫۰۸ لات نمونه‌ای است که ۰٫۰۴، ۰٫۰۲، ۰٫۰۱ و Runner برابر ۰٫۰۱ می‌دهد.
- پس از TP1 استاپ ریسک اولیه را کاهش می‌دهد؛ پس از TP2 به نقطه ورود نزدیک/منتقل می‌شود و Runner با ATR Trailing پیش می‌رود.
- چون هدف‌های مرحله‌ای و تریلینگ مجازی/مدیریت‌شده توسط EA هستند، MT5 یا VPS باید هنگام رسیدن قیمت به آن‌ها روشن و متصل باشد. اگر ترمینال بسته شود، SL محافظتی سرور همچنان باقی می‌ماند، اما TP جزئی و تریلینگ تا زمان اجرای مجدد EA فعال نمی‌شوند.

## ۸) چه زمانی کپی واقعی را روشن کنم؟

تا زمانی که چند سیگنال واقعی را در Journal و گزارش Paper Lab بررسی نکرده‌ای، Live را روشن نکن.

وقتی آماده شدی:

1. در Inputs مقدار `InpSignalLiveAllowed` را از false به true تغییر بده و تأیید کن.
2. پس از بارگذاری مجدد اکسپرت، دکمه `SIGNAL` را در نوار کنترل پنل روشن کن.
3. حالت `SIGNAL_MODEL_D_COMBINED` را حفظ کن تا Order Roulette و Volume Roulette هر دو روی معاملات واقعی همان کانال اعمال شوند.
4. کپی زنده را ابتدا روی حساب Demo از نوع Hedging آزمایش کن.

در زمان آغاز، `g_SignalLiveEnabled` خاموش است و باید از پنل جداگانه روشن شود. تغییر Input به‌تنهایی سفارش واقعی را شروع نمی‌کند.

## ۹) قالب پیام‌های پشتیبانی‌شده

نمونه Market:

```text
BUY XAUUSD NOW
SL: 4040
TP1: 4060
TP2: 4070
TP3: 4080
```

نمونه Limit با محدوده ورود:

```text
SELL GOLD LIMIT
ENTRY: 4050-4052
SL: 4060
TP1: 4045
TP2: 4040
TP3: 4035
```

نمونه اصلاح و بستن:

```text
SL: 4052
TP1: 4070
TP2: 4080
```

```text
SL TO BE
```

```text
CLOSE TRADE
```

پیام باید جهت، نماد (مگر اینکه تک‌نماد بودن منبع را آگاهانه فعال کرده باشی)، SL و حداقل یک TP روشن داشته باشد. سیگنال‌های مبهم، سیگنال‌هایی با BUY و SELL هم‌زمان، پیام‌های بدون SL/TP و سیگنال‌های جدیدتر از `InpSignalMaxAgeSeconds` رد می‌شوند. عکس یا اسکرین‌شات فقط برای بازبینی دستی ذخیره می‌شود؛ در نسخه فعلی از روی تصویر با OCR سفارش ساخته نمی‌شود.

## ۱۰) ارتقا از نسخه قبلی و نکات مهم

- قبل از جایگزینی، اگر از v5.02 معاملات Signal Copy باز داری، آن‌ها را ببند یا جداگانه تعیین تکلیف کن. v5.03 از Magic و Comment namespace جدید `NX503` و Global Variable prefix جدید `NXS503` استفاده می‌کند و عمداً پوزیشن‌های قدیمی را به موتور جدید واگذار نمی‌کند.
- منطق پله‌های رولت نسخه 5.03 از ابتدا و به‌صورت مستقل برای هر منبع آغاز می‌شود.
- این بسته شامل فایل `.session` یا `.env.local` واقعی نیست؛ پس از راه‌اندازی خودت آن‌ها را ایجاد کن و در اختیار کسی نگذار.
- پل Python و ورود واقعی به تلگرام هنوز با حساب و کانال تو آزمایش نشده‌اند؛ تا زمانی که حساب خودت احراز و لاگ `Listening Telegram` را ندیده‌ای، اتصال واقعی تأییدشده نیست.
- سورس MQL5 در این محیط به MetaEditor دسترسی نداشته و **کامپایل واقعی نشده است**. قبل از Live، F7، Strategy Tester و حساب Demo الزامی‌اند.

## گزارش بررسی همین بسته

- `signal_bridge.py` و `manage_sources.py` با `py_compile` بررسی شدند.
- تست خودکار Parser برای قالب‌های BUY/SELL، XAUUSD/GOLD، ویرایش SL/TP، BE، CLOSE، CANCEL و RSS-to-signal اجرا شد و PASS داد.
- یک مرور ساختاری ایستا روی سورس MQL5 انجام شده است؛ این جایگزین کامپایل MetaEditor، تستر استراتژی یا آزمایش اجرای واقعی روی بروکر نیست.

- تغییر Mode فقط ورودی‌های جدید را از مسیرهای غیرانتخابی مسدود می‌کند؛ پوزیشن‌ها، سفارش‌های معلق و SL/TP موجود دست‌نخورده باقی می‌مانند. سفارش معلق ممکن است پس از تغییر Mode اجرا شود.
- `CLOSE NIXO POSITIONS ONLY` پوزیشن‌های Nixo را می‌بندد و Pending Orderها را حفظ می‌کند. Pending Order حفظ‌شده می‌تواند بعداً اجرا شود.
- ثبت snapshot مدیریتی به ازای پوزیشن برای TP1/TP2/Runner/BE.
- سقف `InpMaxOpenRiskPct` به کنترل مشترک Manual/Strategy/External ارتقا یافته است.
- دکمه `ADVANCED REPORT` خروجی CSV از تاریخچه و پوزیشن‌های باز می‌سازد؛ داشبورد HTML آفلاین با `reporting/generate_report.bat` ساخته می‌شود.
- منابع Telegram و RSS هم‌زمان و با enable مستقل قابل اجرا هستند. Adapter اجرایی اختصاصی X و TradingView هنوز در این نسخه نیست و باید جداگانه به `NIXO_SIG_V1` متصل شود.

جزئیات و محدودیت‌های تست در `CHANGELOG_FA_v5.04.md` آمده است.
